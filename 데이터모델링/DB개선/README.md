# DB개선 — SafeWork AI 데이터 설계 문서

ML팀(신찬우)이 생성한 3개 SQL 파일을 DB팀(강주호)에게 전달.
파일은 `DB개선/output/` 폴더 안에 있음.

---

## 파일 1 — `checklist_item_insert.sql`

### 들어있는 데이터
법령 조항 2547개 + 체크리스트 질문 835개가 하나의 파일에 순서대로 담겨 있음.
법령이 먼저 들어가야 체크리스트가 법령을 참조할 수 있어서 순서가 고정됨.

### 법령 데이터 (`law_article` 테이블)
- 기존 `ai_safework_full.sql`의 법령 데이터와 동일한 article_id 사용
- 총 5개 법령, 2547개 조항
  - 산업안전보건법
  - 산업안전보건법 시행령
  - 산업안전보건법 시행규칙
  - 산업안전보건기준에 관한 규칙
  - 중대재해 처벌 등에 관한 법률

### 체크리스트 데이터 (`checklist_item` 테이블)

| 컬럼 | 내용 | 예시 |
|------|------|------|
| item_code | 항목 식별 코드 | `SIF-CON-0001` (건설업), `SIF-MFG-0001` (제조업) |
| category | 작업 종류 | `굴착 작업`, `가공 설비를 이용한 작업` |
| question | 체크리스트 질문 | `굴착면의 기울기가 안전 기준을 준수하고 있는가?` |
| description | 관련 실제 산재 사고 요약 | `[무너짐] 2018년...` |
| target_industry | 업종 | `건설업` / `제조업` |
| risk_weight | 가중치 (지지 사고 건수) | `7` (실제 7건 산재 기반) |
| law_ref | 관련 법령 article_id 목록 | `"1489,1486"` |

### 법령 연결 방식 (law_ref)
SIF 사고 데이터 기반으로 생성된 질문마다 관련 법령 조항을 AI가 매핑.
`law_ref`에 관련 `law_article.article_id` 값을 콤마로 구분해서 저장.

```
예: law_ref = "1489,1486"
→ law_article에서 article_id 1489, 1486 조회하면 해당 법령 조항 전문 확인 가능
```

## 파일 2 — `ml_encoding_map_create_insert.sql`

### 들어있는 데이터
ML 모델 학습에 사용된 인코딩 매핑 정보 151개.
원본 한글 값 → 정수 변환 기준표.

### 테이블 구조 (`ml_encoding_map` — 신규 테이블)

| 컬럼 | 내용 | 예시 |
|------|------|------|
| feature_name | 피처 이름 | `연령`, `규모`, `발생형태` |
| original_val | 원본 한글 값 | `40세~44세`, `5~9인` |
| encoded_val | 정수 인코딩 값 | `5`, `1` |
| enc_type | 인코딩 방식 | `ordinal` (순서형), `label` (명목형) |

### 포함된 피처 목록

| 피처 | 인코딩 방식 | 클래스 수 |
|------|------------|----------|
| 규모 | ordinal | 9개 |
| 연령 | ordinal | 10개 |
| 근무기간 | ordinal | 8개 |
| 건설공사금액 | ordinal | 8개 (건설업 전용) |
| 재해정도 | ordinal | 8개 |
| 발생형태 | label | 23개 |
| 질병종류 | label | 9개 |
| 세부질병종류 | label | 32개 |
| 종업종 | label | 44개 |

> 성별·지역·산업은 원핫 인코딩 → 컬럼명 규칙으로 처리해서 별도 테이블 없음
> (예: `성별_남`, `지역_경기`, `산업_농업` 등 0/1 컬럼)

## 파일 3 — `ml_training_data_create_insert.sql`

### 들어있는 데이터
ML 모델 학습에 사용된 전처리 완료 데이터 약 126만 행.
인코딩까지 완료된 상태의 최종 학습 데이터.

### 테이블 구조 (`ml_training_data` — 신규 테이블)

| 컬럼 | 내용 | 예시 |
|------|------|------|
| dataset_type | 데이터 종류 | `accident` (발생형태 예측), `disease` (질병종류 예측) |
| industry | 업종 | `건설업`, `제조업`, `광업` 등 |
| year | 연도 | `2017` ~ `2025` |
| features | 인코딩된 피처 전체 (JSON) | `{"규모_enc": 1, "연령_enc": 5, ...}` |
| target_enc | 예측 대상값 (정수) | `6` (발생형태 `떨어짐`에 해당) |
| target_col | 예측 대상 컬럼명 | `accident_type` / `disease_type` |

### 데이터 규모

| 업종 | 발생형태 데이터 | 질병종류 데이터 |
|------|--------------|--------------|
| 건설업 | 267,808행 | 41,688행 |
| 제조업 | 272,493행 | 60,941행 |
| 광업 | 24,824행 | 23,545행 |
| 기타의사업 | 404,326행 | 43,488행 |
| 운수·창고·통신업 | 95,070행 | 7,194행 |
| 소규모 통합 | 20,965행 | 1,880행 |

> [주의] 파일 크기 약 627MB. DB 서버 용량 확인 후 적재 권장.

## 데이터 흐름 요약

```
실제 산재 사고 데이터 (SIF)
    ↓ AI 분류 + LLM 체크리스트 생성
체크리스트 질문 (작업 × 발생형태)
    ↓ 임베딩 유사도 + LLM 법령 매핑
checklist_item_insert.sql
  └── law_article (2547개 법령 조항)
  └── checklist_item (835개 질문 + law_ref)

KOSHA 마이크로데이터 (2017~2025)
    ↓ 전처리 + 인코딩
ml_training_data_create_insert.sql (126만 행)
ml_encoding_map_create_insert.sql (인코딩 기준표)
```
